## Summary

This week, I mainly focused on Android development and learning more about how mobile applications are designed and built.

One of our tasks was to choose an application design from Dribbble, Figma, or a similar platform and recreate it using Kodular. I chose a recipe app design from Dribbble and worked on rebuilding it as closely as I could.

While working on the task, I focused on both the visual side of the application and the logic behind it. I had to think about how the different screens connect, how information moves between them, and how the features work together.

Outside of the task, I also spent some time looking into Android development in general and learning more about what Android developers usually do and what their work is like.

We also had a Tech Talk on Thursday about Quality Assurance (QA). I found this really interesting because it was very different from what I had imagined QA to be. I thought it was mostly about manually checking things, but I learned that QA can involve writing code, automated testing, bug reporting, and having a lot of responsibility in the release process.

## Completed Tasks

- Chose a recipe app design from Dribbble and started recreating it in Kodular.
- Built the main screens for the app, including login, sign-up, home, recipe details, and favorites.
- Connected the screens so the user can move through the app properly.
- Used one recipe details screen for multiple recipes instead of creating a separate screen for each one.
- Added recipe images, ingredients, cooking and preparation times, and interactive checkboxes.
- Added a Favorites feature using TinyDB so saved recipes can appear on a separate screen.
- Researched Android development and learned more about what Android developers usually work on.
- Attended the Thursday Tech Talk about QA, automated testing, bug reports, and the release process.

## Skills Learned

This week helped me understand a lot more about how a mobile application works behind the design. Before this task, I mostly thought about how an app looks, but now I have a better idea of how much logic is happening behind each screen and feature.

I also became more comfortable using Kodular and working with blocks. I learned how to connect screens, pass information between them, reuse one screen for different data, and save information using TinyDB.

Another thing I learned was the importance of following a design and sticking to the requirements. There were parts of the app that I personally would have changed, but the point of the task was to recreate the design I chose, so I had to work within that instead of changing everything based on my own preferences.

The QA Tech Talk also gave me a completely different view of testing. I learned more about automated testing, bug reports, and how QA helps make sure an application is actually ready before it reaches the user.

## Challenges and Solutions

One of the main challenges was making the application feel connected rather than like a group of separate screens. I had to figure out how to pass information between screens and how to make one recipe details page show different information depending on which recipe the user selected. Using one reusable screen helped solve that and also made the app easier to manage.

The Favorites feature was another challenge because I needed the app to remember which recipes were saved. I used TinyDB to store that information and then used it to decide which recipes should appear on the Favorites screen.

I also had some layout issues, especially when I wanted the main content to scroll while keeping the bottom navigation bar fixed. I had to reorganize the screen layout so the scrolling section and the navigation bar were separate.

The biggest challenge for me this week was not having access to an Android device. Since the app is being made for Android, I could not properly test how it would look and behave on an actual device. I could build the screens and logic in Kodular, but I could not fully confirm how everything would work once the app was running. Unfortunately, I was not able to get access to an Android phone during the week, so I started looking into using an Android emulator on my laptop instead.

Another challenge was following the inspiration design closely. There were definitely things I would have done differently if it were my own app, but this made me realize that development is not always about personal preference. Sometimes the job is to follow the design and requirements that are already there.
