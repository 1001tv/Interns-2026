# Task Report: 1001 Multi-Platform Review & Version Control Workflow

## Task Title
Version Control Workflow Though the Process of Submitting the Multi Platform REview Week-01 Report

## Task Objective
To complete and submit the 1001 multi-platform review report while setting up and following a professional Git and GitHub version control workflow with the team.

## Requirements
* Set up a local Git environment and clone the project repository.
* Follow the project structure and folder naming conventions specified in the root `README.md`file.
* Create a dedicated branch, stage changes, commit, and open a Pull Request (PR) to merge into `main`.
* Format and submit the report using the provided markdown report template also mentioned on the `README.md`file.

## Implementation Details
* **Environment Setup:** Cloned the repository locally and authenticated my VS Code environment with my work GitHub account.
* **Workflow Execution:** Created a feature branch, organized the directory structure, added the required report file (`week-01.md`), staged the changes, and pushed them to remote.
* **Pull Request & Peer Review:** Opened a PR on my branch for merging into `main` and reviewed several colleagues' PRs to check their work.
* **Knowledge Sharing:** Assisted a teammate from scratch by guiding them through installing Git, cloning the repo locally, and walking them through the full version control workflow.

## Challenges Faced
* **Directory Structure Ambiguities:** The primary `interns` directory wasn't initially present in the repo, and the `daily-reports` subfolder listed in the roadmap wasn't fully specified in the structure.
* **VS Code Authentication:** Encountered authentication errors when pushing to remote because my local VS Code was linked to my personal GitHub account instead of my work email.
* **Empty Folder Commits:** Tried committing empty directories, which triggered a "no changes to commit" state since Git doesn't track empty folders.
* **Requirements & Template Adaptation:** Faced minor misunderstandings with the mentor regarding exact submission deliverables, and had to reframe my existing notes to fit the strict layout of the newly provided template.

## Solution
* Coordinated with the team to establish the shared directory structure (which a fellow intern created) and clarified remaining folder structure requirements directly with the mentor during the daily standup.
* Authenticated my work account in VS Code to fix push permissions.
* Added the `week-01.md` file inside the directory so Git could track the changes properly.
* Refreshed my memory on Git commands using Gemini summaries and a handful of YoutTube videos.
* Carefully reviewed the template instructions multiple times to ensure my notes were formatted concisely and hit every key requirement.

## Testing Performed
* Verified local branch status and commit history using standard Git commands.
* Successfully executed `git push` without authentication or path syntax errors.
* Checked GitHub to ensure the feature branch pushed correctly and the Pull Request was opened cleanly with all required files in place.

## Final Result
Successfully submitted the `week-01-report.md` file using the proper PR workflow, refreshed my overall Git/GitHub fluency, and helped onboard a teammate to the project setup.

## Additional Notes
This task was a great refresher on version control workflows. Working alongside peers on GitHub made the process very engaging, and clarifying requirements with the mentor during daily standups really helped keep everything on track.
